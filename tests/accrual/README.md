# Тесты расчёта по «Отчёту по начислениям» (`tests/accrual`)

Воспроизводимые тесты парсера XLSX «Отчёт по начислениям», классификатора корзин,
финансового ядра и товарной аналитики, а также общего XLSX-reader и старого
парсера отчёта реализации (регресс).

## Запуск

Из корня репозитория с установленными зависимостями (`npm ci`), Node.js 20+:

```bash
npm run test:accrual
```

Команда компилирует **реальные модули проекта** (`app/app/lib/...`, TypeScript →
CommonJS в `node_modules/.cache/accrual-tests/build`, в git не попадает) и запускает
встроенный раннер `node --test`. Ни сети, ни Python, ни файлов вне репозитория не
нужно; тесты не читают `~/Downloads`.

## Что покрыто

| Файл | Что проверяет |
|---|---|
| `accrual-parser.test.mjs` | парсер: заголовки по названиям, ошибки со списком колонок, период, дубли `ID начисления`, суммы в копейках, форматы (t="str", sharedStrings, «Excel-style»), классификатор корзин |
| `accrual-calc.test.mjs` | формула прибыли, `no_tax_revenue`, неполная себестоимость, товарная аналитика и reconciliation (Σ прибыль товаров = `netProfit` до копейки), метод наибольших остатков |
| `accrual-property.test.mjs` | 400 случайных отчётов (**seed 12345**, LCG) + 2000 случайных раздач (**seed 777**), независимый «оракул» |
| `accrual-snapshot.test.mjs` | снимок истории `ozon-accrual-xlsx-v1`: сборка из настоящего ядра, сериализация → чтение, строгая проверка (повреждённый снимок ≠ нулевой расчёт), маржа (число / 0 / `null`), товарная аналитика, независимость от текущего каталога, старые снимки не задеваются |
| `accrual-pdf-model.test.mjs` | содержимое PDF нового формата (чистая модель): период, итог, категории, «—» у неопределимой маржи, предварительный результат, предупреждения. Рисование на canvas/jsPDF в Node не проверяется — только визуально |
| `xlsx-reader.test.mjs` | общий reader (`xlsx-safe-read.ts`): обход бага SheetJS 0.18.5 для `t="str"`; старый `parseOzonReport` на синтетическом отчёте реализации |

## Откуда ожидания

Ожидаемые значения **не вычисляются проверяемой формулой**:

* `helpers/expected.mjs` — литералы для синтетического отчёта `basic`, посчитанные вручную
  (в комментарии — исходные строки и вывод), плюс раздача копеек, проверенная отдельным
  расчётом на дробях;
* `accrual-property.test.mjs` — оракул внутри файла (простая арифметика на копейках и
  BigInt-раздача с точным сравнением дробей), а не вызов функций проекта;
* старый парсер — значения заданы самим фикстуром (`helpers/realization-fixture.mjs`);
  единственная «характеристика» (`netRevenue`) снята с `mprof-production` e71c97a.

## Фикстуры

Все XLSX собираются **в памяти** (`helpers/xlsx-builder.mjs` + минимальный ZIP-писатель
`helpers/zip.mjs`) в стиле Ozon: ячейки без `r`-атрибутов, строки `t="str"` с числовыми
ссылками `&#x…;`, даты — Excel-serial. Данные вымышленные (`ART-A/B/C`, «Товар А/Б/В»).

## Чего здесь нет намеренно

* Реальных отчётов и любых данных продавца (товаров, артикулов, названий).
* Проверки на реальных отчётах Ozon: сверка июньского отчёта по начислениям и сравнение
  старого `ozon-parser` на реальных отчётах реализации выполняются **локально** и в репозиторий
  не входят.
